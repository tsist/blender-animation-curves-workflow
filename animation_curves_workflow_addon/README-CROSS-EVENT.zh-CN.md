# 双角色与灯光持久事件（0.3.5 开发候选）
先在原“双角色事件 · 保存与接续”捕获有效双人 head.Y 记录，再在“双角色灯光事件 · 保存与接续”选灯对象与现有energy中间键，最终预览确认关联。新记录独立保存，不自动修改旧两类事件JSON。三方改时后旧双人记录会过期，这是保留原记录的结果，不会自动重绑。

仅标准自有双rig的head.Y与一盏独占POINT/AREA灯energy；目标键LINEAR/CONSTANT与FREE，其他键全部保护。灯须精确Blender5.2.1默认Emission→OutputLight节点树，白色、Strength1、Weight0，不能有树动画/额外节点/修改输入。不是任意节点灯适配，也不修改材质、音乐或空间接触。

共同delta保两个offset，禁止越锁键/占位/不精确float32时刻。当前播放头若会改变目标求值则拒绝，请手动移到锁定端点再预览。灯名/data名、唯一归属、Action/slot/完整内容漂移即过期，不猜测替代身份。源由名称与内容校验，不是抗恶意认证。

确认时一次复制三个Action，三绑定和新JSON一起提交；失败回滚自己的事务，外部内容不擅删。Undo恢复旧绑定、记录和旧动作求值，可能丢失已动画通道未打键手动输入；请先另存。原Action保护标志与记录只在保存工程后持久，不自动保存。锁键不等于邻区间形状不变。

本版本开发中。Linux Blender5.2.1限定测试，尚待最终独审及GUI；不能称完整跨域WM或攻防片验收。

灯Action首版仅允许唯一energy通道；color或其他非energy动画整体拒绝，避免把动态原生输入误当稳定身份。其他灯的数据绑定与当前值作为非目标完整保护。持久见证不含当前energy求值，切帧本身不使记录过期；但是否允许改时仍有当前播放头保护。
