# 双角色事件：保存与接续（0.3.4候选）

在动画曲线侧栏「双角色事件 · 保存与接续」使用：
1. 捕获/替换：明确两个标准自有角色骨架及各head.Y非端点键，预览Action、slot和帧后确认。只写本Scene的一条事件记录，不改动画。已有记录会明确替换，不自动追踪手改键。
2. 另存工程。未保存的记录只在当前会话中；冷开后「检查已保存关联」重新核对UUID、名称、Action/slot及完整曲线见证。
3. 接续改时：填写共同delta，最终预览显示双方源/目标键、offset与邻锁键。确认后一次复制两个动作，更新两绑定和事件记录。再次保存后可继续冷开操作。

仅两条head.Y的LINEAR/CONSTANT与FREE手柄。其他键（含原Bezier）不改；锁定时刻不等于邻区间形状不变。不支持任意骨、音乐、空间接触或通用事件图。原有普通对象事件面板及event_state数据保持不变，旧文件无新记录时需显式捕获。

记录漂移时拒绝，不猜测重绑：角色/Action改名、UUID歧义、换Action/slot、手改键或手柄都会使记录过期。明确重新捕获可替换已知格式的旧记录；非法/未知格式不自动清除，不能以替换隐藏损坏。

Undo恢复旧动作绑定、事件记录及旧动作求值，可能丢失已动画骨捕获前的未打键手动输入；建议先另存。Redo恢复本次同步。事务失败回滚与原生Undo不是同一保证。原Action保护标志仅在保存工程后持久；不自动保存，不写外部备份。

仅Linux Blender5.2.1候选测试范围；Windows/macOS未验。当前文件不代表已完成GUI验收，最终资格以包外报告为准。

当前帧限制：本窄路径不自动重求值/覆盖手动姿态。若改时会改变当前播放头处head.Y的求值，请先手动将播放头移到未变的锁定端点，再预览提交；例如本测试帧60的线性转头段会被明确拒绝。此限制不改变动画时间或替用户切帧。
