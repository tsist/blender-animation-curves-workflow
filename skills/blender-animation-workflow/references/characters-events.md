# 角色、原生通道与事件

在已保存工作副本操作，先确定帧率、单位、角色关系和需要保持的卡点。

## 角色与姿态

Object 模式的「简形角色模板 · 开发候选」提供双节圆柱和简形人形 FK。圆柱为 3 骨、无四肢。人形为 18 骨，每腿由大腿与小腿两段组成，朝前为 −Y，上方为 +Z，头胸有正面标记。模板创建后用原生关键帧编排动作。

在 Pose 模式选标准自有角色及活动骨，用「自有角色 · 姿态单轴关键帧」设置、移动或删除受支持通道。膝按物理屈曲输入，支持 0–150°，其余受支持变形骨使用局部 Euler 旋转。先用「当前帧双膝只读体检」核对实际几何，局部 Euler 的负号需结合静置姿态解释。

「为所选骨骼记录当前旋转姿态」将支持的旋转写入当前帧。目标键冲突、受影响的自动手柄、未打键偏移或不支持的通道会使操作拒绝。需要准备旧 AUTO 通道时，使用显式的复制动作入口，并检查新旧 Action 绑定。

支撑判断结合腿部和地面实际播放，查看落地、摆动与恢复。后台小腿端盖诊断及固定端盖求解具有特定 Linux x86_64 Blender 构建、模板和输入守卫，使用前按实际预检结果确认资格。Windows 可用的当前帧膝体检与原生姿态编辑仍可用于独立修正和复核。

## 普通通道

Object 模式选对象，在「动画曲线」面板选择通道，读取当前值并检查所选通道，然后设置、移动或删除关键帧。常用目标包括对象位置、Euler 旋转、缩放，以及受支持的手控灯强度／颜色、材质颜色／发光。

受其他领域工具管理的目标遵循其所有权检查。保留手控辅助对象的独占 Action，修改后回到所属领域工具检查。

## 完整片段事件

「完整片段事件 · 捕获 / 改时」处理局部事件窗口。

1. 选择「普通对象」或「人形四组」。普通对象填写 1–8 个精确 MESH／EMPTY 名称。人形组填写双方骨架、根、接触灯和对应动画材质。
2. 填写事件 ID、开始帧、当前接触帧、结束帧和窗口外锁帧。每条参与曲线在接触处需要唯一原生键。
3. 使用「只读检查完整片段事件」，随后「预览并准备提交」，核对报告后「提交预览中的完整片段事件」。
4. 捕获完成后切换到改时，填写新接触帧，重复检查、预览和提交。提交后看接触前后姿态、灯材强调和后续锁定事件。

普通对象路径要求当前场景内无父级的本地 MESH／EMPTY、独占原生 Action、XYZ Euler、默认 delta 和正尺度，支持已有位置／旋转／缩放通道及 LINEAR／BEZIER。人形路径要求受支持的模板和完整身体／根通道。驱动、NLA、共享 Action、约束或超预算输入按报告处理。

## 多事件工程与锁

「多事件工程 · 时间 / 锁 / 关系」读取同一场景的多个接触。

1. 刷新事件列表，选择事件，填写「新接触帧」。
2. 点击预览，核对受影响的双方、效果、窗口和关系，再提交。
3. 需要保持该接触时刻时启用「切换所选事件的时间锁」，预览并提交锁操作。
4. 复杂的捕获、采用、先后关系、同步关系或世界位置锁使用「高级请求」，将 `animation-event-project-v1` JSON 放入 Blender 文本块，再选择该文本块预览和提交。

高级请求使用 `capture`、`adopt`、`retime`、`set_relations`、`set_lock`。`after` 表示明确的最小帧间隔，`sync` 表示偏移与容差。空间锁引用实际世界顶点或骨骼点。参与者和锁点应从当前工程读取。

音乐事件先确定节拍、起音或段落候选的原始秒数，再映射到场景帧。当前插件可按指定帧校正和锁定事件，音频分析需由已有分析工具提供。原始采样时钟、候选和最终选择应随工程保管。

## 人工修改接续

用 Graph Editor 修改其他事件或窗口外曲线后，保存副本，再读取当前事件。记录仍一致时可继续改时。手改落入已绑定窗口时，检查会报告过期或冲突，核对后用项目的 `adopt` 采用当前曲线，再重新预览。

AUTO 手柄在原生编辑与保存后可能重新求值。以保存并重开的实际曲线为准，同时检查手改目标的值和固定句柄。Undo 恢复旧绑定与求值，已动画轴上的未打键姿态应提前另存。

如有已安装的兼容 `blenderctl`，可选用 `animation inspect|run`、`project-inspect|project-run` 或 `channel-inspect|channel-edit`。先读该安装版本的 `--help`，提供实际文件 SHA、精确请求与资源清单，再核对独立重开结果。
